1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
CloudReclaim is an ownership-aware, calendar-aware cloud resource reclamation 
system engineered specifically for university cloud laboratories. Universities 
provision cloud infrastructure (virtual machines, GPU training instances, 
storage volumes, and Jupyter notebook servers) across courses and departments. 
However, when semesters end, faculty depart, or breaks occur, idle resources 
continue running 24/7, accumulating thousands of dollars in unnecessary cloud spend.

CloudReclaim addresses this operational failure by combining:
  1. Multi-signal idle detection (CPU + Memory + Network + GPU + Disk I/O)
  2. Academic calendar awareness (Semesters, Breaks, Exam Weeks, Maintenance)
  3. Schema-validated policy configuration (JSON/YAML Draft-07 schemas)
  4. Human-in-the-loop approval workflow (Grace periods, Notifications, Extensions)
  5. Synthetic telemetry generator & Automated experiment benchmark suite

The project has reached 100% COMPLETION, representing a fully operational 
end-to-end platform with complete backend services, database persistence, 
multi-signal decision logic, policy validation, Web Admin & Instructor dashboard, 
and comprehensive test coverage.

3. END-TO-END SYSTEM WORKFLOWS & DATA FLOWS
--------------------------------------------------------------------------------

[FLOW 1: TELEMETRY INGESTION & DATA ENGINE]
  Cloud Provider Adapters / Telemetry Generator
        │
        ├──> Resource Registry ─────────> Store Owner Metadata & Tags ──┐
        ├──> Multi-Signal Telemetry ────> Store CPU, Mem, Net, GPU, Disk │ ──> SQLite DB
        └──> Academic Calendar ─────────> Store Terms, Breaks, Exams ────┘

[FLOW 2: MULTI-SIGNAL DETECTION & DECISION ENGINE]
  Scheduled Scan Trigger / Admin Manual Scan
        │
        ▼
  Fetch Active Cloud Resources from Database
        │
        ├──> Check Ownership: Is Owner Assigned?
        │       ├── NO  ──> Mark Action: ORPHANED (status = 'orphaned')
        │       └── YES ──> Check Semester: Is Course Semester Active?
        │                    ├── NO  ──> Mark Action: EXPIRED (status = 'semester_expired')
        │                    └── YES ──> Pull 7-Day Multi-Signal Telemetry Metrics
        │                                 │
        │                                 ▼
        │                         Check Burst Workload: Max CPU > 50%?
        │                          ├── YES ──> Mark Action: ACTIVE (Burst Workload Protected)
        │                          └── NO  ──> Check Multi-Signal Thresholds:
        │                                       CPU < 5% AND Mem < 10% AND Net < 1KB AND GPU < 5%?
        │                                        ├── NO  ──> Mark Action: ACTIVE
        │                                        └── YES ──> Check Break Period: Current Date in Break?
        │                                                     ├── YES ──> Pre-Break CPU >= 5%? ──> YES ──> ACTIVE
        │                                                     └── NO  ──> Mark Action: IDLE (Flagged)

[FLOW 3: HUMAN-IN-THE-LOOP APPROVAL & SAFETY ENFORCEMENT]
  Flagged Request Created in Pending Queue
        │
        ▼
  Notification Dispatch to Resource Owner / Instructor
        │
        ├──> APPROVE ──> Create State Snapshot ──> Stop Resource & Reclaim Cost
        ├──> EXTEND  ──> Check Extensions Used < Max (2)? ──> YES ──> Add 14 Days to TTL
        ├──> REJECT  ──> Mark Request Rejected ──> Keep Resource Active
        └──> NO RESPONSE (Deadline Expired)
                │
                ▼
        Safety Re-Check: Is CPU Currently Active?
                ├── YES ──> Abort Reclamation & Reset Status to Active
                └── NO  ──> Create State Snapshot & Reclaim Resource


4. DELIVERED WORKS & CORE CODE MODULES
--------------------------------------------------------------------------------
1. synthetic_generator.py (Telemetry Generator):
   - Generates 36 cloud resources, 6 lab courses, 5 users, and 4,320 telemetry points.
   - Generates owner tags (owner_email, department, course_code, project, environment, cost_center).
   - Exports standalone JSON (synthetic_dataset.json) and YAML (synthetic_dataset.yaml).

2. decision_engine.py (Classification Engine):
   - Evaluates multi-signal metrics, ownership state, course semester status, and burst spikes.
   - Outputs DecisionResult with confidence_score (0.0 - 1.0) and risk_score (0.0 - 100.0).

3. calendar_parser.py (Academic Calendar Classifier):
   - Parses Fall/Spring/Summer semesters, break periods, exam weeks, and maintenance windows.
   - Automatically extends grace period deadlines during university break periods.

4. baseline_evaluator.py & baseline.py (Benchmark Evaluator):
   - Compares single-metric (CPU-only) baseline against multi-signal prototype.
   - Calculates Precision, Recall, Confusion Matrix (TP, FP, TN, FN), and False Positive Rate.

5. schemas/policy_rules.schema.json & policy_validator.py (Policy Schema Validator):
   - JSON/YAML Draft-07 schemas defining numerical bounds, types, and required policy keys.
   - Integrates validation directly into config.py for safe Admin UI rule updates.

6. reclaimer.py (Reclamation & Approval Workflow Engine):
   - Handles instructor approval queue, grace period countdowns, extension limits (max 2),
     resource state snapshots, and final safety re-verification before shutdown.

7. Web Application & Dashboard (app.py, routes/, templates/, static/):
   - Full Flask web interface featuring dark glassmorphism theme, KPI summaries,
     interactive Chart.js visualizations, resource inventory, approval queue, and admin rules.
