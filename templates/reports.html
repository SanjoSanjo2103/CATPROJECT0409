Error Analysis & Design Rationale

Why does the baseline produce more false positives?

The baseline uses a single metric (CPU < 5%) which doesn't account for:

  • Burst workloads (e.g., GPU training every 3 days) — low average CPU, but genuinely active
  • Memory-intensive services — low CPU but high memory utilization
  • Semester context — resources during active semesters shouldn't be reclaimed aggressively

Why is the prototype more accurate?

  • Multi-signal detection: CPU + Memory + Network + GPU must ALL indicate idle
  • Calendar awareness: Expired semesters are flagged immediately; breaks get extended grace
  • Burst detection: Any spike > 50% CPU in the window prevents false flagging
  • Ownership validation: Orphaned resources are escalated to admin, not silently deleted
  • Final safety check: Re-check utilization before executing reclamation (race condition guard)
